# Примеры реальных журналов событий (Event Logs)

В данной папке собраны репрезентативные датасеты, воспроизводящие выгрузки цифровых следов из реальных корпоративных информационных систем предприятий. Наборы данных предназначены для тестирования алгоритмов реконструкции графов процессов (DFG, Heuristic Miner) и демонстрации работы модуля преподавателю.

## 1. 1C_ERP_Заказ_Клиента.csv
* Предметная область: управление продажами и логистикой (Order-to-Cash, B2B).
* Источник данных: выгрузка регистра состояний заказов из конфигураций «1С:ERP Управление предприятием» / «1С:Управление торговлей».
* Объем: 500 заказов (трасс), свыше 5 000 событий.
* Структура колонок:
  * НомерЗаказа: идентификатор трассы процесса (Case ID, например, ЗК-1042);
  * ДатаВремя: точная метка времени фиксации статуса (Timestamp, YYYY-MM-DD HH:MM:SS);
  * Статус: название выполненной бизнес-операции (Activity, например, Регистрация заказа, Резервирование товара);
  * Ответственный: исполнитель операции (Resource, менеджер, кладовщик или робот);
  * Клиент, Сумма, Склад: контекстные атрибуты сделки.
* Заложенные сценарии и аномалии:
  * Основной поток (Happy path, ~65%): прямая цепочка от регистрации до закрытия сделки.
  * Циклы и возвраты (Rework loop, ~20%): отклонение условий и повторные согласования скидок.
  * Узкие места (Bottlenecks, ~15%): задержки из-за ожидания поставщика и напоминания об оплате.
  * Досрочные отмены (~10%): отказ клиента до внесения предоплаты.

## 2. ServiceDesk_Инциденты_ITSM.csv
* Предметная область: техническая поддержка и управление ИТ-услугами (ITIL / ITSM).
* Источник данных: выгрузка истории переходов тикетов из систем Jira Service Management / Naumen Service Desk.
* Объем: 400 инцидентов (трасс), свыше 3 200 событий.
* Структура колонок:
  * Ticket_ID: номер тикета (Case ID, например, INC-2026-1015);
  * Timestamp: дата и время смены статуса (Timestamp);
  * Activity: статус обработки инцидента (Activity, например, Классификация, Диагностика);
  * Assignee: ответственный сотрудник или диспетчер (Resource);
  * Support_Tier: уровень поддержки (Tier 1, Tier 2, User);
  * Priority, Service_Name: приоритет и целевой корпоративный сервис.
* Заложенные сценарии:
  * Быстрое решение инцидента первой линией поддержки (Tier 1).
  * Эскалация на вторую линию (Tier 2) с запросом диагностических логов у пользователя.
  * Цикл возврата на доработку (Re-open): отклонение решения пользователем при повторном сбое.

## 3. Банк_Кредитный_Конвейер.csv
* Предметная область: банковский сектор, кредитный скоринг физических и юридических лиц (Loan Approval).
* Источник данных: процессинговый лог автоматизированной банковской системы (АБС).
* Объем: 500 кредитных заявок, свыше 3 800 событий.
* Структура колонок:
  * ЗаявкаID: номер заявки на кредит (Case ID, например, APP-50012);
  * Время: метка времени события (Timestamp);
  * Действие: этап рассмотрения (Activity, например, Скоринговая оценка, Запрос в БКИ, Проверка СБ);
  * Сотрудник: автоматический модуль или специалист (Resource);
  * СуммаКредита, КредитныйРейтинг: категория заемщика и запрашиваемый лимит.
* Заложенные сценарии:
  * Быстрый отказ на этапе автоматического скоринга при высоком риске.
  * Углубленная проверка с запросом 2-НДФЛ и согласованием службы безопасности.
  * Успешная выдача кредита с подписанием договора через СМС.

## 4. Эталонный_Процесс_1С_IEEE_1849.xes
* Стандарт: международный формат IEEE 1849-2016 (eXtensible Event Stream).
* Назначение: эталонный XML-файл для демонстрации совместимости модуля с академическими и промышленными системами Process Mining (ProM, Celonis, Disco).
* Содержит стандартные пространства имен:
  * concept:name: имя операции (Activity);
  * time:timestamp: точная метка времени со смещением часового пояса;
  * org:resource: имя ответственного лица;
  * lifecycle:transition: состояние жизненного цикла события (complete).
